# D2F Global source and build guide

This repository contains the implemented mobile app, backend API, and web Admin
dashboard. The current Android source version is `1.1.1+2015`. The signed ARM64 release
APK is `output/apk/D2F-Global-1.1.1+2015-arm64-v8a.apk`; the prior APK is retained.

## Source inventory

| Path | Contents |
| --- | --- |
| `lib/` | Flutter application, screens, models, API client, authentication, widgets, tracking and PDF services |
| `assets/` | App images, signup illustration, bundled font and font license |
| `android/`, `ios/`, `web/`, `macos/`, `linux/`, `windows/` | Flutter platform projects; the delivered and validated mobile release is Android |
| `pubspec.yaml`, `pubspec.lock` | Flutter/Dart dependencies and locked versions |
| `backend/src/` | Express API, authentication, permissions, Admin/customer/staff routes and tracking allocation |
| `backend/prisma/` | PostgreSQL schema, seed and complete migration history, including permanent tracking reservations |
| `backend/package*.json`, `backend/Dockerfile` | Locked backend dependencies and deployment build configuration |
| `backend/.env.example`, `backend/env.production.example` | Configuration templates with placeholders |
| `admin-dashboard/` | React/Vite Admin source, tests, dependency lock and hosting configuration |
| `test/`, `integration_test/`, `test_driver/`, `backend/test/` | Flutter, integration and API checks |
| `tool/` | Android release builder and icon resource generator |
| `design/` | Brand source artwork, design notes, verification screenshots and release verification records |
| `output/pdf/` | Client milestone completion report |

## Get the source

```sh
git clone https://github.com/rehanhamayun/d2f_app_full.git
cd d2f_app_full
```

Use a Flutter SDK that satisfies the Dart constraint in `pubspec.yaml`, an Android
SDK/JDK compatible with the checked-in Gradle configuration, and Node.js 22 for
the API. Use PostgreSQL 16 for local backend verification.

## Android app

```sh
flutter pub get
flutter test
flutter analyze --no-fatal-infos
flutter build apk --release --split-per-abi --dart-define=API_BASE_URL=https://d2f-api-production.up.railway.app
```

For the current Flutter SDK, use `python3 tool/build_android_release.py` with Flutter on PATH to build the signed ARM64 APK in a disposable workspace; this avoids the SDK integration-test plugin release registrant issue.

The build outputs are under `build/app/outputs/flutter-apk/`. Flutter regenerates
ignored platform/build files as needed. Android build codes include the ABI
offset applied by Flutter; `2015` is the current source base build number.

Existing production updates require the original release signing key and the
private `android/key.properties` configuration. These must be transferred
securely, outside GitHub. Without that configuration, the project uses its debug
signer and cannot update an installation signed with the production key.

To regenerate launcher resources, install Python Pillow and run
`python3 tool/generate_brand_icons.py`. The source is
`design/02_D2F_Wordmark.png`.

## Backend API

Create a separate local PostgreSQL database, then:

```sh
cd backend
npm ci
cp .env.example .env
```

Edit `.env` with your local database URL and private configuration. Then:

```sh
npx prisma generate
npx prisma migrate deploy
npx prisma db seed
npm run dev
```

Local development seeding includes sample records. Production bootstrap requires
private Staff/Admin passwords and a strong JWT secret; see
[`backend/DEPLOYMENT.md`](backend/DEPLOYMENT.md). Run `npm test` only against a
dedicated test database configured through `DATABASE_URL`. Tracking reservations
are intentionally permanent, including those generated by tests.

To connect an Android emulator to the local API, run from the repository root:

```sh
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000
```

Production deployment applies the checked-in migrations before API startup.
Follow the backend deployment and authentication guides for hosting variables,
optional provider setup and backup requirements.

## Web Admin dashboard


See [`admin-dashboard/README.md`](admin-dashboard/README.md) for API-origin/CORS

## Intentionally outside source control

Production secrets, `.env` files, account passwords, signing keys, local database
data/backups, dependency folders and temporary authoring files are excluded.
The supplied release APK is included under `output/apk/`; generated build folders
are excluded. Supply private values through the hosting platform or secure handover.
Their exclusion does not remove application source. This repository records the
implemented scope; later roadmap features are described separately in the
milestone review and client report.

## D2F Connect release build

Run `python3 tool/build_android_release.py` with Flutter on PATH. This builds in a
disposable directory and excludes the development-only integration-test plugin from
that release pubspec, working around its registration issue in the current SDK.
The real source, lockfile and integration tests remain intact. Existing private
signing configuration is used locally; signing keys are never published.

Connect operations and setup are documented in [CONNECT_WORKFLOW.md](CONNECT_WORKFLOW.md).
